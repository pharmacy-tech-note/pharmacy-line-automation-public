# Step ①：LINEからの通知を受信する

## このStepで実現すること

LINEの通知を受けてGASが応答を返す、受付システムの入口を作ります。

## 関数の役割

| 関数 | 役割 |
| --- | --- |
| doPost(e) | LINEから通知を受け取った際に実行される関数。通知の本文からeventsを取り出します。 |
| createResponse(msg) | LINEサーバーへ返すHTTP応答用の出力を作ります。 |

## 主要な処理の読み方

`e.postData.contents` がLINEから届く通知本文です。`JSON.parse()` でJavaScriptから扱えるデータへ変換し、`json.events` から出来事の一覧を取り出します。本文がないとき、eventsがないときや空のときは応答を返します。

`createResponse(msg)` は `HtmlService.createHtmlOutput("OK")` を返します。msgには呼び出し時の文字列が渡されますが、返す内容はOKです。①ではこの受信と応答までを作ります。Code.gs冒頭の①〜⑦は機能を追加する位置を見渡すための目印です。

## 必要な設定

スクリプトプロパティの登録は不要です。

## 登録と操作

1. [共通手順](../README.md#アカウントと準備)でGoogle・LINEとGASプロジェクトを準備します。
2. [Code.gs](Code.gs)の全文をGASへ貼り付けます。前のStepを使っていた場合はコード全体を置き換えます。
3. 上記の設定値を「プロジェクトの設定」→「スクリプト プロパティ」に登録します。①では登録不要です。
4. doPostをエディタから実行し、権限の認可画面が出たら確認して許可します。
5. 初回は「デプロイ」→「新しいデプロイ」→「ウェブアプリ」、実行ユーザー「自分」、アクセス「全員」で登録します。更新時は「デプロイを管理」→編集→「新バージョン」で反映します。
6. LINE DevelopersのWebhook URLへ /exec のURLを登録し、Webhook利用を有効にします。同じデプロイを更新した場合は登録済みURLを使います。詳しくは[共通手順](../README.md#初回デプロイ)を参照します。

## 動作確認

1. LINE DevelopersでWebhook URLの「検証」を実行し、結果を確認します。
2. GAS「実行数」にdoPostの履歴ができることを確認します。
3. 友だち追加した公式アカウントへテスト用テキストを送り、新しい実行履歴ができることを確認します。

①のコードは受信件数のログを追加していないため、成功確認には実行履歴を使います。

## エラー時の確認箇所

実行履歴がなければ、Webhook URLが/execか、Webhook利用が有効か、ウェブアプリのアクセスが「全員」かを確認します。JSONの解析エラーが表示された場合は登録URLと通知の送信経路を確認します。
